# 出勤模拟器上线方案

## 方案结论

当前项目最适合的上线方式：

`GitHub + Cloudflare Pages + 自定义域名`

原因：

- 项目是静态网页，不需要先买传统云服务器。
- `index.html` 直接引用了根目录和多个子目录资源，适合整站静态托管。
- Cloudflare Pages 免费起步，部署快，自带 HTTPS，后续也方便扩展。

## 当前项目特点

这个项目不是只发布 `dist/` 就够了。

页面入口是根目录的 `index.html`，同时依赖这些资源：

- `style.css`
- `spring.css`
- `life.css`
- `expansion.css`
- `update.css`
- `vendor/lucide.min.js`
- `data/music.js`
- `data/chart-meta.js`
- `data/expansion.js`
- `data/cn-versions.js`
- `judgement.js`
- `gameplay.js`
- `b50.js`
- `collection.js`
- `systems.js`
- `engine.js`
- `dist/app.js`

所以部署时应当发布 **整个项目根目录**，而不是只发布 `dist/`。

## 推荐平台

### 1. 托管平台

推荐：`Cloudflare Pages`

优点：

- 免费额度够前期使用
- 配置简单
- 自带 HTTPS
- 绑定域名方便
- 后续可接 Cloudflare Workers

### 2. 代码托管

推荐：`GitHub`

用途：

- 管理版本
- 连接 Cloudflare 自动部署
- 以后改动后可一键重新上线

### 3. 域名

可选：

- `Cloudflare Registrar`
- `阿里云万网`
- `腾讯云域名`

建议优先选择 `.com`。

## 上线步骤

### 第一步：本地构建

在项目根目录执行：

```bash
npm install
npm run build
```

构建脚本会生成：

- `dist/app.js`
- `dist/app.js.map`

### 第二步：本地自检

上线前至少检查这些内容：

- 首页是否正常打开
- 样式是否完整加载
- 曲绘、图标、数据文件是否正常加载
- 页面脚本是否报错
- 手机端是否能正常进入和操作

## 第三步：上传到 GitHub

建议新建仓库，例如：

`maimai-attendance-simulator`

推送当前项目代码后，再到 Cloudflare Pages 连接该仓库。

## 第四步：创建 Cloudflare Pages 项目

创建项目时建议填写：

- Framework preset: `None`
- Build command: `npm run build`
- Build output directory: `.`

这里的关键点：

- **输出目录不是 `dist`**
- 因为站点入口和大量资源都在项目根目录
- Cloudflare 需要把整个项目目录作为网站内容发布

## 第五步：部署后检查

部署完成后重点检查：

- `index.html` 能否正常访问
- `dist/app.js` 是否返回 200
- `data/music.js`、`data/chart-meta.js` 等是否返回 200
- `assets/` 下图片和图标是否正常
- 控制台是否有 404 或脚本错误
- 刷新页面后是否仍然正常

## 第六步：绑定域名

如果后续要正式开放访问，可以绑定自定义域名。

推荐流程：

1. 购买域名
2. 在 Cloudflare 中接入域名 DNS
3. 在 Pages 项目里绑定域名
4. 等待证书签发完成

完成后即可通过自定义域名访问，并自动启用 HTTPS。

## 预算建议

前期预算可以非常低：

- Cloudflare Pages：`0 元`
- GitHub：`0 元`
- 域名：约 `50-100 元/年`

也就是说，当前阶段基本不需要购买服务器。

## 现阶段不推荐的方案

暂时不建议直接购买：

- 阿里云 ECS
- 腾讯云轻量服务器
- 宝塔面板 + Nginx

原因：

- 需要自己维护服务器
- 需要配置 HTTPS
- 需要处理安全组和运维问题
- 对当前纯静态项目来说属于过度投入

## 后续扩展路线

如果后面要加入以下能力：

- 排行榜
- 云存档
- 登录系统
- 在线活动公告

建议再逐步补后端：

### 轻量后端

- `Cloudflare Workers`

### 需要数据库时

- `Cloudflare D1`
- 或 `Supabase`

## 一句话版本

当前项目最合适的上线方案就是：

`GitHub + Cloudflare Pages + 自定义域名`

并且部署时发布 **整个项目根目录**，不要只传 `dist/`。
